# テスト仕様書

最終更新: 2026-11-12

## 1. テストの進め方

| 項目 | 内容 |
|---|---|
| 方法 | 手で画面を操作して確かめる（手動テスト） |
| 環境 | バックエンド（3000）とフロントエンド（5173）を両方起動。Chrome |
| 使う道具 | Chrome DevTools（Network：通信、Console：ログ、Throttling：通信をわざと遅くする） |
| テストデータ | 薬35件（8カテゴリ＋分類なし＝NULL の新ビオフェルミン1件）。内訳は [DB設計書「5. テストデータ」](database-design.md#5-テストデータ) |
| IDの付け方 | 章ごとに10ずつ区切る。あとから足した章は、空いている番号の続きを使う。**一度付けたIDは変えない**（過去の記録と対応がずれないように） |
| 結果の書き方 | ✅ 合格 / ❌ 不合格 / − 未実施。不合格なら、気づいたことを備考に書く |

**正常系**とは、普通の使い方で正しく動くかの確認です。
**異常系**とは、わざと失敗させたときに、困らない動きをするかの確認です。

## 3. 既知の不具合・観察メモ

| 内容 | 状態 |
|---|---|
| Backspace で「頭痛」→空にしたとき、一度だけ「見つかりませんでした」になった。古い返事が新しい返事を上書きした（返事の追い越し）疑い。再テストでは再現せず | 経過観察。デバウンスで起きにくくなった |
| カテゴリボタンの名前と、DB の category は別物（例: ボタン「かぜ薬」と DB「かぜ薬（のど・鼻）」）。検索は症状で行うので、動きには影響しない | 仕様 |
| 開発モードでは、エラーが2セット出る | 不具合ではない（React の StrictMode が、開発中だけ useEffect を2回動かすため） |

## 4. 今後追加したいテスト

- 自動テスト（Vitest）で、バックエンドの「症状で絞り込む」処理を確かめる
- `&` などの記号を含む症状を入力したとき（URL に入れる前に記号へ変換していないため、壊れる可能性がある）
- 症状ボタンの文字が、DB の symptoms と完全一致しているかを自動で確かめる（T-65 を手で全部やるのは大変なため）
- 薬の詳細表示・絞り込みを作ったら、そのテストケース
