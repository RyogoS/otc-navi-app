# API仕様書

最終更新: 2026-10-16

## 1. 共通のルール

| 項目 | 内容 |
|---|---|
| 住所の始まり（ベースURL） | `http://localhost:3000`（開発中） |
| データの形 | JSON |
| 文字コード | UTF-8。日本語は URL に入れるとき、`%E9%A0%AD` のような記号に変換される（パーセントエンコーディング） |
| 呼び出せる画面 | `http://localhost:5173` だけ（CORS） |
| ログイン | 不要（今のところ） |

## 2. エンドポイント一覧

| メソッド | パス | 内容 | 状態 |
|---|---|---|---|
| GET | `/medicines` | 薬の一覧を取得（症状で絞り込み可） | ✅ |
| GET | `/` | サーバーが動いているかの確認（ひな形。`Hello World!` を返す） | ✅ |
| GET | `/medicines/:id` | 薬を1件取得（詳細） | 📝 |
| POST | `/medicines` | 薬を登録 | 📝 |
| PATCH | `/medicines/:id` | 薬を編集 | 📝 |
| DELETE | `/medicines/:id` | 薬を削除 | 📝 |

## 3. GET /medicines（薬の一覧を取得）

### 送るもの（リクエスト）

| 場所 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| クエリパラメータ | `symptom` | 文字 | いいえ | 絞り込みたい症状。空または省略すると全件 |

クエリパラメータとは、URL の `?` の後ろに `名前=値` の形で付けるおまけ情報のことです。

### 例

```
GET http://localhost:3000/medicines?symptom=頭痛
```

### 返ってくるもの（レスポンス）

**成功（200 OK）:** 薬の配列。該当がなければ空の配列 `[]`（エラーではない）

```json
[
  {
    "id": 1,
    "created_at": "2026-09-23T14:05:35.776598+00:00",
    "name": "バファリンA",
    "category": "解熱鎮痛薬",
    "symptoms": ["頭痛", "発熱", "生理痛"],
    "precautions": "空腹時の服用は避けてください",
    "contraindications": "胃潰瘍のある方は使用しないでください",
    "dosage_instructions": "1回1〜2錠、1日3回まで、4時間以上あけて服用",
    "pregnancy_safe": false,
    "min_age": 15
  }
]
```

### 各項目の意味

| 項目 | 型 | null になる？ | 意味 |
|---|---|---|---|
| `id` | 数字 | いいえ | 薬の番号 |
| `created_at` | 文字（日時） | いいえ | 登録した日時 |
| `name` | 文字 | いいえ | 薬の名前 |
| `category` | 文字 | **なる** | 分類（解熱鎮痛薬、整腸剤など） |
| `symptoms` | 文字の配列 | いいえ | 効く症状のリスト |
| `precautions` | 文字 | なる | 注意点 |
| `contraindications` | 文字 | なる | 使用禁忌（使ってはいけない条件） |
| `dosage_instructions` | 文字 | なる | 用法用量 |
| `pregnancy_safe` | true / false | なる | 妊娠中に使えるか |
| `min_age` | 数字 | なる | 使える最低年齢 |

**フロントエンドで今使っている項目:** `id`、`name`、`category`、`symptoms` の4つ（`type Medicine`）

### 絞り込みのルール

- `symptoms` の配列の中に、`symptom` と**一字一句同じもの**がある薬だけを返す（完全一致）
- 例: `symptom=頭` では、「頭痛」はヒットしない（0件）
- 前後の空白は、フロントエンド側で取り除いてから送る

### 失敗したとき

| 状態 | ステータス | 原因の例 |
|---|---|---|
| サーバー内のエラー | 500 Internal Server Error | Supabase とのやり取りに失敗した |
| 304 Not Modified | 304 | エラーではない。「前と同じなので、ブラウザに保存してあるものを使って」の合図 |

## 4. 予定のエンドポイント（📝）

### GET /medicines/:id（薬を1件取得）

```
GET http://localhost:3000/medicines/1
```

- 成功: 薬1件のオブジェクト（`[ ]` ではなく `{ }`）。成分の一覧も含めたい
- その番号の薬がない: 404 Not Found

### POST /medicines（薬を登録）

送るもの（本文 / Body）:

```json
{
  "name": "新しい薬",
  "category": "解熱鎮痛薬",
  "symptoms": ["頭痛"]
}
```

- 成功: 201 Created と、登録した薬
- `name` が空など、送るものがおかしい: 400 Bad Request
